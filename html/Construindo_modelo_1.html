def create_conn():
    # Defina os parâmetros de conexão
    db_user = os.getenv('DB_USER')
    db_password = os.getenv('DB_PASSWORD')
    db_host = os.getenv('DB_HOST')
    db_port = '5432'
    db_name = 'magic-steps'

    # Crie a URL de conexão
    connection_url = f'postgresql://{db_user}:{db_password}@{db_host}:{db_port}/{db_name}'

    # Crie um engine do SQLAlchemy
    engine = create_engine(connection_url)
    return engine
engine = create_conn()

Distribuição de Motivo de Inativação¶

Nesta análise, estamos considerando a base completa, pois existem mais de uma informação de inativação por aluno. Chamou nossa atenção que alguns dos principais motivos de inativação foram: Conhecimento acima da fase atual, Outras prioridades/trabalho, e Falta de retorno às nossas tentativas de contato. O motivo Mudou de bairro/cidade/distância, mesmo sendo um dos principais, é fácil de entender do ponto de vista do aluno.

No entanto, ao analisar o motivo Falta de retorno, surgem algumas dúvidas: Será que existe uma visita presencial para verificar a situação do(a) aluno(a)? São consideradas possíveis dificuldades tecnológicas para contato do lado do aluno?

Sobre o motivo Outras prioridades/trabalho, para os alunos que trabalham, será que existe uma abordagem que possa ajudar esses alunos, como cargas horárias menores ou maior empatia com suas situações?

Conclusão da Primeira Análise¶

Observamos que, embora as features selecionadas forneçam informações importantes sobre os alunos, elas, isoladamente, não apresentam uma boa correlação com a inativação. Com isso, decidimos retornar à análise da base de dados e selecionar novas informações que possuam uma correlação mais significativa.
